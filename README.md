# Финансовый управляющий

Telegram-бот для совместного бюджета. Записывайте расходы и доходы в закрытой группе обычными сообщениями. Бот разнесёт траты по категориям, покажет остаток бюджета и посчитает, сколько можно отложить.

```text
такси 2500
продукты 12500
зп 350000
```

По умолчанию суммы учитываются в тенге. Расход с одной суммой попадёт в «Без назначения». Ответьте на вопрос бота, например «такси», чтобы уточнить категорию той же записи.

## Что умеет бот

- Сводки по месяцу и по всей истории, импорт текстовой переписки из JSON-экспорта Telegram Desktop.
- Месячные ориентиры из истории расходов и ручные лимиты. Доступная сумма по каждой категории ограничена общим остатком.
- Учёт поступлений отдельно от расходов. Оценка накоплений оставляет резерв на оставшуюся часть месячного бюджета.
- Кнопки для основных действий и уточняющие вопросы, если в записи не хватает деталей.

## Подключение

Понадобятся Node.js 24 и собственный бот Telegram. Создайте бота в [@BotFather](https://t.me/BotFather) через `/newbot`. В `/setprivacy` выберите **Disable**, затем добавьте бота в закрытую группу расходов. Если бот уже состоит в группе, добавьте его заново после смены режима.

В PowerShell скопируйте настройки и откройте файл:

```powershell
Copy-Item config.example.env .env
notepad .env
```

В Linux или macOS используйте `cp config.example.env .env` и свой редактор. Укажите `TELEGRAM_BOT_TOKEN` и часовой пояс в `TIME_ZONE`. `GEMINI_API_KEY` можно оставить пустым для локального разбора коротких записей.

```sh
node --env-file=.env bot.mjs discover
```

Отправьте в вашей группе `/id@имя_бота`, скопируйте отрицательный `TELEGRAM_CHAT_ID` из консоли в `.env` и запустите бота:

```sh
node --env-file=.env bot.mjs run
```

Отправьте `/menu`, чтобы включить кнопки под полем ввода.

### Docker Compose

Запускайте из-под обычного пользователя Linux. После настройки `.env` создайте каталог учёта и подставьте UID и GID владельца файлов:

```sh
mkdir -p data
export SERVICE_UID=$(id -u) SERVICE_GID=$(id -g)
docker compose up -d
docker compose logs --tail=30 bot
```

Пока ID группы неизвестен, его также можно получить через `docker compose run --rm bot discover`. Данные Docker хранятся в `data/ledger.json`. Для переноса учёта сделайте копию файла после остановки бота.

## Команды

| Команда или сообщение | Результат |
| --- | --- |
| `/menu` | Показать кнопки в группе |
| `Этот месяц`, `Вся история` | Сводка расходов и поступлений |
| `Бюджет`, `бюджет подробно` | Остаток и лимиты по категориям |
| `бюджет 750000`, `бюджет транспорт 30000` | Задать общий лимит или лимит категории |
| `Сколько отложить` | Поступления, расходы и оценка накоплений за месяц |
| `/goal 120000 12` | Рассчитать месячный взнос для цели на 12 месяцев |
| `Советы`, `Уточнить записи` | Идеи по расходам и записи, которые ждут уточнения |
| `/income 50000 подработка` | Явно записать поступление |
| `/fix 12 такси 2500`, `/skip 12` | Исправить или исключить запись |

## Деньги и накопления

Укажите общий остаток, включая отложенное, и суммы по целям. Например:

```text
сейчас всего 450000
отложено на отпуск 150000
отложено на подушку 100000
```

Кнопка «Накопления» показывает общий остаток, суммы по целям и свободные деньги. Новые расходы и поступления меняют остаток. Повторная запись по той же цели заменяет сумму, а ноль закрывает цель. Кнопка «Сколько отложить» учитывает свободные деньги и резерв на расходы по бюджету. Если часть операций ведёте вне чата, укажите свежий общий остаток.

Вопрос «Сколько осталось денег?» показывает свободный остаток и накопления по участникам. Для этого каждый указывает `остаток 15000` со своего аккаунта или подтверждает скриншот со своими счетами. Суммы показываются по последним записям.

## Скриншоты и чеки

Отправьте фото без подписи или с подписью `скрин`, `чек` или `баланс`. Бот покажет прочитанную сумму операции, баланс или суммы накоплений. Ответьте «да», чтобы подтвердить запись, или «нет», чтобы отменить. Для баланса отдельного счёта бот спросит, считать ли его общим остатком. Обычную текстовую запись с суммой в подписи бот обработает как текст.

В подписи с отдельным заголовком `Остаток` можно добавить строку `и 12000 на второй карте`. Бот включит её в черновик. Текстовые сообщения вида `Остаток 15,600` с отдельными строками по целям учитываются как личный остаток и накопления автора. Чтобы обработать старое фото или сообщение, ответьте на него `прочитай`.

Распознавание требует Gemini. Изображение передаётся в Gemini; поддерживаются фото и файлы PNG, JPG и WebP до 8 МБ. Исходное изображение в учёте не сохраняется.

## Импорт истории

В Telegram Desktop откройте нужный чат и выберите **⋮ → Экспорт истории чата → Машиночитаемый JSON**. Остановите процесс учёта перед импортом. Для экспорта из той же супергруппы:

```sh
node --env-file=.env bot.mjs import /path/to/result.json
```

Для обычной группы или прежней личной переписки добавьте `--before` и момент перехода на учёт через бота, например `--before 2026-10-01T12:00:00+05:00`. Бот возьмёт сообщения строго до этой границы. При повторном импорте того же архива уже обработанные записи пропускаются.

В Docker поместите JSON в `data/`, выполните `docker compose stop bot`, затем `docker compose run --rm bot import /app/data/result.json` с нужными аргументами и снова запустите `docker compose up -d bot`.

## Данные и Gemini

Учёт хранится в локальном JSON. При настроенном Gemini текст записей о расходах и текст импортируемой переписки могут отправляться в Gemini для классификации. Бот также может отправить сводку расходов для генерации советов. Новые поступления и записи накоплений обрабатываются локально. Остатки, лимиты и оценка накоплений рассчитываются локально. Перед подключением Gemini ознакомьтесь с [условиями сервиса](https://ai.google.dev/gemini-api/terms).

Храните `.env`, ключи, архивы переписки и `data/` вне репозитория.
